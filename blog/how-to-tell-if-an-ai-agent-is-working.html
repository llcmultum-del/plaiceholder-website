How to Tell If an AI Agent Is Actually Working

2026-11-12

Ask a company whether its AI tools are working and you will usually get a feeling, not a number. People say it seems faster, or that the team likes it. That is not nothing, but it is not an answer either. MIT's NANDA initiative reported in 2025 that only about 5% of the generative AI pilots it studied produced rapid revenue gains, with the rest showing little or no measurable effect on profit and loss. Futurum Group's 2026 survey of 830 IT decision-makers found 43% still unsure how to measure the business value of their AI. Some of those tools may well be helping. The trouble is that nobody can show it.

Write down "before" first

Most measurement problems start before the tool is switched on. If nobody records how long the task takes today, how often it goes wrong, and how much of it sits in a queue, there is nothing to compare against later. A month in, "it feels quicker" is the only evidence left.

The baseline does not need to be elaborate. For a single repeatable task, three numbers usually cover it: how many items go through in a week, how long each one takes a person, and how many get sent back or corrected. Count them for two or three weeks before anything changes. A spreadsheet is fine.

Measure the task, not the tool

A common mistake is tracking what the software does instead of what the business gets. Number of prompts run, number of messages drafted, number of logins: these show activity, and activity is easy to produce. What matters is whether the task itself got cheaper, faster, or more accurate.

This is one reason narrow agents are easier to judge than broad assistants. An agent that checks supplier invoices against purchase orders has an obvious scoreboard: invoices checked, mismatches caught, mismatches missed, hours a person no longer spends on it. A general chat tool spread across a whole department has no single scoreboard, so its value turns into an argument. The MIT report made a related point: back-office work like this showed some of the clearest measured returns, even though most AI budgets went to sales and marketing.

Check accuracy, not only speed

Speed is the number everyone reaches for, because it improves straight away. But an agent that finishes in seconds and is wrong one time in ten can cost more than the manual process it replaced, since someone now has to find and fix the errors downstream.

So keep a sample under review. For the first few weeks, have a person check a fixed share of the agent's output, record what it got wrong, and sort the errors into types. After that the sample can shrink, but it should not disappear. Inputs change: suppliers redesign their invoices, a CRM field gets renamed, a new product line appears. An agent that was accurate at launch can drift without anyone noticing unless someone keeps looking.

None of this is complicated, and most of it is done before or after the build rather than during it. That is why we set it up this way. Each PlAIceholder agent handles one defined task, so there is one set of numbers to watch. The pilot runs on a small batch of real records, so accuracy is checked against actual work before anything scales up. And the care plan exists partly to keep watching those numbers after launch, when drift tends to show up. If an agent is working, the figures will show it. If it is not, it is better to find that out in week three than in month nine.
